## Как это работает (схема авторизации портала)

- **Порталный пароль** → HMAC-токен `portal` (заголовок `X-Auth-Token` или `?password=`).
  Проверка: `_vcs_check_password()` в `tasks/api/main.py`.
- **Админский пароль** → токен `admin` (админка, управление AI).
- Голосовой агент авторизуется портальным паролем из `voicecall.env` → получает токен,
  при протухании переавторизуется сам.
- Read-эндпоинты воронки обзвона — открытые (без пароля), пишущие — за паролем.

## Правила

1. Новый секрет → строка в таблицу выше + значение в `СЕКРЕТЫ.local.md`.
2. Значение секрета в коде/доке репо — запрещено (в `main.py` остались legacy-дефолты
   паролей — вынести в техдолг, см. 10-ТЕХДОЛГ).
3. `СЕКРЕТЫ.local.md` продублирован владельцем вне ПК (менеджер паролей/заметки) —
   на случай смерти диска.
4. Ротация: пароли портала/админки меняются в env на VPS (`systemctl restart tasks-api`
   после смены) + в `voicecall.env` на ПК (перезапуск задачи агента).
