**Принцип разделения:** VPS слишком мал для моделей (Vosk big ~1.8 ГБ > вся RAM VPS),
поэтому всё «тяжёлое» (LLM, STT, TTS, телефония) живёт на ПК, а VPS только проксирует
и хранит данные. ПК за cone-NAT; связь ПК→VPS всегда исходящая (SSH reverse tunnel,
HTTP-поллинг агента).

## Компоненты

### VPS (Ubuntu, root@195.208.119.67)

| Сервис | Порт | Что делает | Управление |
|---|---|---|---|
| nginx | 80/443 | статика всех модулей из `/var/www/okk/` + прокси | `systemctl reload nginx` |
| tasks-api | 127.0.0.1:8601 | FastAPI-бэкенд (`tasks/api/main.py`), uvicorn | `systemctl restart tasks-api` |
| recruiter | 127.0.0.1:8501 | Streamlit AI-рекрутёр | systemd |
| SSH-туннель (вход) | 127.0.0.1:21434 → Ollama ПК; 127.0.0.1:25001 → Silero ПК | AI-прокси | поднимает ПК |
| Novofon-прокси | `/novofon-callapi/`, `/novofon-dataapi/` | JSON-RPC прокси к Novofon (их API требует IP-whitelist — белый IP только у VPS) | nginx |

БД — SQLite `/var/www/okk/tasks/api/tasks.db`. Миграции — идиом `ALTER TABLE ... ADD COLUMN`
в `init_db()` (try/except OperationalError), выполняются при старте tasks-api.

### ПК владельца (Windows 11, вход юзера = запуск всего)

| Компонент | Запуск | Что делает |
|---|---|---|
| `dispatch_agent.py` | задача `STH-Dispatch-Agent` (логон) | поллит портал, звонит через Novofon (pyVoIP SIP), распознаёт Vosk, говорит Silero/edge-tts, шлёт результаты |
| Ollama :11434 | `STH-Ollama-Serve-User` (логон) | LLM (qwen3:0.6b/1.7b/8b) для чата портала, нормализации ответов, детекции роботов |
| SSH-туннель | `STH-AI-Tunnel-User` (логон) | `ssh -R 21434:...:11434 -R 25001:...:5001` на VPS, автоперезапуск в цикле |
| Silero TTS :5001 | поднимает вотчдог | локальный TTS-сервер (venv `C:\ProgramData\sth\silero-venv`) |
| Вотчдог | `STH-Portal-Watchdog` (логон + каждый час) | чинит Ollama/Silero/туннель, toast при сбое |

Все задачи — user-context, триггер «при входе», запускаются через VBS-шим
`C:\ProgramData\sth\run-hidden.vbs` (без вспышки окон). Подробности и грабли —
`08-RUNBOOK.md`.

### Поток данных обзвона (главный бизнес-процесс)

```
Портал (voicecall/index.html)
  └─ загрузка базы XLSX / ручной ввод → POST /voicecall/upload-contacts
  └─ «Начать обзвон» → dispatch_state='requested'
Агент на ПК (поллинг каждые ~20с)
  └─ claim контакта → Novofon start.employee_call (перезвон на нашу SIP-линию)
  └─ диалог: TTS-вопрос → Vosk-распознавание → dialog.py (сценарий)
  └─ POST /voicecall/dispatch/result (ответы, вердикт, длительность)
  └─ фоном: запись разговора Novofon → пере-распознавание big-моделью →
     пере-валидация ответов LLM → recheck-transcript (уточнения, переклассификация)
Портал: воронка кампании, карточки контактов, ⚠-флаги для рекрутёра
```

## Деплой (кратко; детально — 06)

- `git push origin main` → GitHub Actions (`.github/workflows/deploy.yml`):
  rsync репо → VPS `/var/www/okk/`, сборка sales, `setup-server.sh` (nginx-конфиги
  + рестарт tasks-api), smoke-тест.
- **Файлы `voicecall/*.py` — локальные для агента**: деплой = git pull уже есть на ПК
  (репо и есть рабочая копия) + перезапуск задачи `STH-Dispatch-Agent`.
- Фронтенды-статика едут тем же rsync без сборки (кроме sales).

## Ключевые технические решения (и почему)

| Решение | Причина |
|---|---|
| Всё тяжёлое на ПК, VPS только прокси | VPS 1 vCPU/960МБ; Vosk big не влезает |
| SSH reverse-туннель, а не проброс портов | ПК за NAT; исходящее соединение всегда работает |
| Агент поллит портал (не push) | ПК недостижим извне; поллинг прост и надёжен |
| SQLite, не Postgres | один писатель (tasks-api), объёмы малы |
| Один main.py на 116 эндпоинтов | исторически; рефакторинг в roadmap (10-ТЕХДОЛГ) |
| pyVoIP 1.6.8 + 5 monkey-патчей | библиотека сырая; патчи в `phone_call.py` с комментариями-обоснованиями |
| Novofon API через nginx-прокси VPS | Novofon требует IP-whitelist, у ПК динамический IP |
