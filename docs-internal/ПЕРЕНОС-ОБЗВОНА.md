# Автообзвон кандидатов — паспорт и перенос на другой компьютер

> Самодостаточный документ: что это, из чего состоит, как поднять с нуля на
> новой машине и как проверить, что всё живо. Версия: 28.07.2026.
> **Секретов здесь нет** — только указано, где они лежат (см. раздел 5).

---

## 1. Что это за система

Робот-рекрутёр обзванивает базу кандидатов, задаёт вопросы анкеты, распознаёт
ответы и раскладывает людей по трём корзинам: **ЦЕЛЕВЫЕ** (годен) /
**СПОРНЫЕ** (нужен взгляд рекрутёра) / **НЕЦЕЛЕВЫЕ** (недозвон, автоответчик,
стоп-фактор). Рекрутёр открывает портал и работает только с годными.

Всё распознавание, синтез речи и AI-анализ — **локальные**, данные кандидатов
не уходят во внешние AI-сервисы.

## 2. Из чего состоит (два контура)

```
   Рекрутёр (браузер) ──HTTPS──► VPS portalsth.ru (Ubuntu)
                                  ├─ nginx (443)
                                  ├─ FastAPI :8601  (кампании, воронка, отчёты)
                                  ├─ SQLite tasks.db (контакты, ответы, записи)
                                  └─ прокси к API Novofon (нужен статический IP)
                                        ▲ исходящий HTTP-поллинг (~20с)
                                        │
   ЭТОТ ПК — «агент обзвона» ───────────┘
   ├─ dispatch_agent.py  — забирает контакты, звонит, шлёт результаты
   ├─ SIP/RTP (UDP) ◄────► Novofon ◄────► кандидат
   ├─ Vosk (распознавание) + Silero/edge-tts (голос) + Ollama (анализ)
   └─ SSH reverse-туннель → VPS (портал ходит в локальные AI по туннелю)
```

**Важно:** машина агента не принимает входящих соединений — она сама
опрашивает портал. Переносится только ЭТОТ контур; VPS остаётся как есть.

## 3. Что именно переносим

### 3.1 Код (из git)

Репозиторий проекта, папка **`voicecall/`**:

| Файл | Роль |
|---|---|
| `dispatch_agent.py` | главный цикл: поллинг портала, оркестрация, пост-обработка |
| `phone_call.py` | механика звонка: SIP/RTP (pyVoIP + 5 патчей), speak/listen, диалог |
| `dialog.py` | сценарий, разбор ответов, детекторы (автоответчик/робот/перезвон) |
| `stt.py` | Vosk: малая модель в реальном времени + большая по записи |
| `tts.py` | синтез речи: edge-tts + Silero, кэш фраз |
| `call_api.py` | API Novofon (звонки, записи, стоимость, статус линии) |
| `silero_server.py` | локальный сервер синтеза речи :5001 |
| `_sip_config.py` | чтение настроек из env-файла |
| `index.html` | страница обзвона на портале (деплоится на VPS через CI) |

Вспомогательные скрипты — в `scripts/` (запуск агента, туннель, вотчдог).

### 3.2 Модели (НЕ в git, ~4.5 ГБ — качаются отдельно)

Лежат в `C:\ProgramData\sth\`:

| Что | Размер | Откуда |
|---|---|---|
| `vosk-model-ru-0.42` | ~3.5 ГБ | alphacephei.com/vosk/models |
| `vosk-model-small-ru-0.22` | ~87 МБ | там же |
| `silero-model` + `silero-venv` | ~700 МБ | ставится скриптом Silero |
| Ollama: `qwen3:1.7b`, `qwen3:0.6b`, `qwen3:8b` | ~7 ГБ | `ollama pull` |

Пути моделей Vosk можно переопределить переменными окружения
`VOSK_MODEL_DIR` и `VOSK_SMALL_MODEL_DIR`.

### 3.3 Настройки и секреты

Файл **`C:\ProgramData\sth\voicecall.env`** — ключ=значение, 10 параметров:

```
SIP_SERVER, SIP_PORT, SIP_USER, SIP_PASS          — SIP-линия Novofon
NOVOFON_API_KEY, NOVOFON_API_SECRET               — API Novofon
NOVOFON_EMPLOYEE_ID, NOVOFON_VIRTUAL_NUMBER       — кого/с какого номера звонить
PORTAL_URL, PORTAL_PASSWORD                       — доступ к порталу
```

Плюс `C:\ProgramData\sth\ai-tunnel.key` — приватный SSH-ключ для туннеля к VPS.

**Значения** — в `docs-internal/СЕКРЕТЫ.local.md` (он в `.gitignore`, живёт
только на машине владельца). Перенести их нужно вручную, не через git.

### 3.4 Автозапуск (Планировщик заданий Windows)

Четыре задачи, все **в контексте пользователя**, триггер «при входе в систему»,
запуск через VBS-шим `C:\ProgramData\sth\run-hidden.vbs` (чтобы не мигали окна
консоли):

| Задача | Что запускает |
|---|---|
| `STH-Dispatch-Agent` | `scripts/run-dispatch-agent.ps1` — сам обзвонщик |
| `STH-Ollama-Serve-User` | локальный сервер Ollama |
| `STH-AI-Tunnel-User` | SSH-туннель к VPS (11434→21434, 5001→25001) |
| `STH-Portal-Watchdog` | следит, что всё живо, поднимает упавшее |

⚠️ Не заменять VBS-шим на прямой вызов powershell — вернутся вспышки окон.
⚠️ Задачи должны быть в контексте пользователя, не SYSTEM (SYSTEM не читает
пользовательский SSH-ключ).

## 4. Требования к новой машине

| Параметр | Требование |
|---|---|
| ОС | Windows 10/11 (код кроссплатформенный, но автозапуск сделан под Windows) |
| CPU | 4+ ядра — распознавание идёт в реальном времени во время разговора |
| RAM | 8–16 ГБ (Vosk ~1.8 ГБ + Ollama 2–6 ГБ + буферы) |
| GPU | не обязателен |
| Диск | ~15 ГБ под модели |
| Сеть | только исходящие: SIP/RTP (UDP) к Novofon, HTTPS к порталу, SSH к VPS. Входящие порты не нужны, NAT — ок |
| Python | 3.10+ |

**Зависимости ставить только из `voicecall/requirements.txt`**, не набирать
руками: `pyVoIP`, `vosk`, `edge-tts`, `imageio-ffmpeg` (конверсия аудио для
телефонии), `sounddevice`+`numpy` (локальный тест без SIP) и **`audioop-lts`** —
обязателен на Python 3.13+, иначе pyVoIP не заработает (модуль `audioop`
удалён из стандартной библиотеки).

**Silero живёт в ОТДЕЛЬНОМ виртуальном окружении** `C:\ProgramData\sth\silero-venv`
(там `torch`, `flask`, `waitress`) — в основной Python их ставить не нужно.

**Одна машина = одна SIP-линия = один звонок за раз.** Больше линий — больше
экземпляров агента с разными SIP-учётками.

## 5. Пошаговый перенос

1. **Код + зависимости — установщиком.** Склонировать репозиторий и запустить
   в PowerShell:
   ```
   .\voicecall\install_windows.ps1
   ```
   Он проверит Python, создаст `C:\ProgramData\sth\`, скопирует туда шаблон
   `voicecall/env.example` → `voicecall.env` и поставит всё из
   `voicecall/requirements.txt`.
2. *(если ставишь вручную)* создать `C:\ProgramData\sth\` и выполнить
   `pip install -r voicecall/requirements.txt`.
3. **Модели.** Скачать Vosk (обе), развернуть в `C:\ProgramData\sth\`.
   Поставить Ollama и вытянуть модели:
   ```
   ollama pull qwen3:1.7b
   ollama pull qwen3:0.6b
   ollama pull qwen3:8b
   ```
   Silero — по инструкции проекта (создаёт `silero-venv` и `silero-model`).
4. **Секреты.** Перенести вручную (флешка/менеджер паролей, НЕ через git):
   - `C:\ProgramData\sth\voicecall.env` — заполнить **все 10** параметров из
     раздела 3.3. Шаблон `voicecall/env.example` содержит все ключи с
     пояснениями, нужно только подставить значения;
   - `C:\ProgramData\sth\ai-tunnel.key` — приватный SSH-ключ;
   - публичный ключ должен быть в `authorized_keys` на VPS.

   ⚠️ Пропущенный ключ вылезет только в момент звонка (агент упадёт на
   `require(env, "…")`). Проверить заполненность — командой из раздела 6.
5. **VBS-шим.** Создать `C:\ProgramData\sth\run-hidden.vbs`:
   ```vbs
   Set objShell = CreateObject("WScript.Shell")
   objShell.Run "powershell.exe -NoProfile -ExecutionPolicy Bypass -File """ & WScript.Arguments(0) & """", 0, False
   ```
6. **Автозапуск.** Создать 4 задачи из раздела 3.4 (пользовательский контекст,
   триггер «при входе», действие — `wscript.exe //B "…run-hidden.vbs" "…скрипт.ps1"`).
7. **IP в Novofon.** Звонки идут через прокси на VPS, поэтому менять
   IP-whitelist в кабинете Novofon при переезде ПК **не нужно** — именно ради
   этого прокси и сделан.
8. **Перезагрузить** ПК и пройти проверку из раздела 6.

## 6. Проверка, что всё поднялось

```bash
# портал жив
curl https://portalsth.ru/tasks/api/health              # {"ok":true}

# агент виден порталу (главный признак)
curl https://portalsth.ru/tasks/api/voicecall/agent-status   # online: true

# AI-цепочка через туннель
curl https://portalsth.ru/tasks/api/ai/health           # online: true, models: 3

# локальный синтез речи
curl http://127.0.0.1:5001/health
```

Все ли настройки заполнены (печатает только имена ключей, не значения):

```bash
python -c "import sys;sys.path.insert(0,'voicecall');from _sip_config import load_env;e=load_env();need=['SIP_SERVER','SIP_PORT','SIP_USER','SIP_PASS','NOVOFON_API_KEY','NOVOFON_API_SECRET','NOVOFON_EMPLOYEE_ID','NOVOFON_VIRTUAL_NUMBER','PORTAL_URL','PORTAL_PASSWORD'];m=[k for k in need if not e.get(k)];print('НЕ ЗАПОЛНЕНЫ:',m) if m else print('все 10 ключей на месте')"
```

Состояние SIP-линии глазами Novofon (между звонками «Не зарегистрирован» —
это нормально, агент регистрируется только на время звонка):

```bash
python -c "import sys;sys.path.insert(0,'voicecall');import call_api;from _sip_config import load_env,require;e=load_env();print(call_api.get_sip_line_state(require(e,'NOVOFON_API_SECRET'),'0125878'))"
```

Финальная проверка — **тестовая кампания на один номер** через портал.

## 7. Как это работает (для понимания при разборе)

Один звонок:

1. Агент опрашивает портал (~20с) → видит кампанию «запущена».
2. Прогревает кэш синтеза фраз сценария.
3. Забирает контакт (атомарно, чтобы два агента не взяли одного).
4. **Регистрируется в SIP и ждёт, пока регистрацию увидит Novofon** (~2с —
   критично, см. раздел 8).
5. Просит Novofon перезвонить на нашу линию и свести с кандидатом.
6. Диалог: озвучил вопрос → слушает → разобрал ответ → следующий шаг/стоп.
   На каждой реплике проверки: «просит перезвонить» → автоответчик → ринг-бэк.
7. Отправляет результат на портал.
8. **Фоном**: забирает запись у Novofon, пере-распознаёт большой моделью,
   сверяет ответы, при расхождении ставит «⚠ проверить». Пока идёт проверка,
   контакт помечен «⏳ проверяется» — статус ещё может измениться.

## 8. Грабли, на которые уже наступали (не повторять)

- **Novofon видит SIP-регистрацию с задержкой ~2 секунды**, а локальная
  библиотека рапортует «готово» за ~120 мс. Если попросить перезвонить сразу,
  Novofon ответит `sip_offline` и звонка не будет. Агент теперь дожидается
  статуса именно от Novofon.
- **В LLM-проверку «человек или робот» нельзя подавать речь нашего бота** —
  модель видит робота (нашего же) и записывает в роботы кандидата. Только
  дорожка кандидата + защита: назвал возраст → живой, не переклассифицируем.
- **Словарь распознавания шага не должен содержать лишних слов**: на шаге
  «Возраст» слова-согласия («конечно», «хорошо», «окей») побеждали числа.
- «Работало, а теперь нет» = регрессия наших правок, а не среда. Сначала diff,
  потом теории про сеть.
- Тесты только через `python -m pytest tasks/api/tests/ -q`. Известный
  несвязанный красный: `test_ai_cache.py::TestStreamReplay`.
- После правки любого файла в `voicecall/` — перезапустить задачу
  `STH-Dispatch-Agent`, иначе продолжит работать старый код.
- Кириллица ломает консоль Windows: логи читать через Python с
  `encoding='utf-8'`, не через `type`/`cat`.
