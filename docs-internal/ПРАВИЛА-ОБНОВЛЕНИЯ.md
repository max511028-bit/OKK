# Правила обновления документации

> Главное правило: **документация обновляется в том же коммите, что и код.**
> Коммит, меняющий поведение системы без обновления доки, — неполный.

## Матрица «изменил X → обнови Y»

| Что изменилось в коде | Какой документ обновить |
|---|---|
| Добавил/удалил/переименовал эндпоинт в `main.py` | `02-БЭКЕНД-API.md` (строка в таблице) |
| Новая таблица или колонка БД (миграция в `init_db`) | `03-БАЗА-ДАННЫХ.md` |
| Логика звонка: пайплайн, статусы, детекция, пере-валидация (`voicecall/*.py`) | `04-ГОЛОСОВОЙ-АГЕНТ.md` |
| Новый статус звонка/контакта или вердикт | `04` (глоссарий) + `02` (если виден в API) |
| Новый модуль портала или существенное изменение существующего | `00-ОБЗОР.md` + `05-МОДУЛИ.md` |
| Топология: новый сервис, порт, туннель, перенос компонента | `01-АРХИТЕКТУРА.md` |
| Деплой: CI, nginx, systemd, автозапуск на ПК | `06-ИНФРАСТРУКТУРА-И-ДЕПЛОЙ.md` |
| Новый секрет/ключ/пароль | `07-ДОСТУПЫ.md` (реестр) + `СЕКРЕТЫ.local.md` (значение, вне git) |
| Новый типовой сбой, диагностированный и вылеченный | `08-RUNBOOK.md` (секция «симптом → диагноз → лечение») |
| Новые правила/структура тестов | `09-ТЕСТИРОВАНИЕ.md` |
| Обнаружен техдолг / закрыт пункт техдолга | `10-ТЕХДОЛГ.md` |
| Крупная фича/фикс задеплоены | `CHANGELOG.md` (одна строка: дата, суть, коммит) |

## Как обновлять

1. Правка должна быть **минимальной и точной** — не переписывай документ, поправь
   затронутые строки/таблицы.
2. Обнови поле «Обновлено: YYYY-MM-DD» в шапке документа.
3. Если изменение не подходит ни под одну строку матрицы — добавь новую строку
   в матрицу (этот файл тоже живой).

## Для ИИ-агентов (Claude и др.)

Перед коммитом любой доработки пройдись по матрице и спроси себя: «какая строка
таблицы задета?» Если задета — обнови документ **в том же коммите**. Это требование
продублировано в `CLAUDE.md` в корне репозитория и обязательно к исполнению.

## Проверка при код-ревью

Ревьюер (человек или ИИ) отклоняет изменение, если поведение системы изменилось,
а документация — нет.
