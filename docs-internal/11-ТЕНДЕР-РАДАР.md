# Тендер-радар

Вкладка портала `/tenders/`. Обходит закупочные площадки, отбирает закупки
под настроенные направления и складывает в свою базу. Задача — заменить
ручной поиск тендеров.

Перенесён на портал 31.07–04.08.2026 из отдельного приложения
(`C:\Users\user\Documents\КЛод\ОКК\tender-radar`, оно осталось как архив).

## Из чего состоит

| Файл | Что делает |
|---|---|
| `tenders/index.html` | вкладка: найденное, направления, площадки, журнал |
| `tasks/api/tenders_api.py` | 21 эндпоинт, подключается в `main.py` через `include_router` |
| `tasks/api/tenders_db.py` | схема и доступ к базе (голый sqlite3, как весь портал) |
| `tasks/api/tenders_pipeline.py` | опрос площадок, дедупликация, отбор |
| `tasks/api/tenders_core/` | ядро без зависимости от хранилища: матчинг + коннекторы |
| `tasks/api/tenders.db` | своя база, **исключена из rsync** — деплой её не трогает |

Всё за паролем портала (тем же, что конструктор обзвона).

## Направления

Иерархия: **группа → направление → ключевые слова**. Слово бывает трёх видов:
`include` (добавляет баллы), `exclude` (отбрасывает закупку), `require` (без
него не берём). Направление берёт тендер, если сумма баллов ≥ порога.

Фильтры направления (пустой список = не применяется):

| Фильтр | Как ищет |
|---|---|
| Города | по региону, заказчику, названию и описанию — **широко** |
| Заказчики | **строго** по полю заказчика |
| Регионы, законы, ОКПД2, площадки | точное/префиксное совпадение |
| Цена от/до | по начальной цене |

Разница между городом и заказчиком сознательная: города площадки кладут
куда попало (в регион, в название заказчика, в текст), а слежка за
конкретной компанией не должна срабатывать на упоминание её в чужой
закупке.

Морфология русская: «аутсорсинг персонала» находит «аутсорсингу
персоналом», но не «аутсорсинг печати».

## Где что собирается

Замер 31.07: **сети портала и домашнего ПК видят разные площадки**.

| Площадка | Портал (VPS) | Дом |
|---|---|---|
| Bidzaar, B2B-Center | ✅ | ✅ |
| Роселторг, Фабрикант, ЭТП ГПБ, ЗаказРФ | ✅ отвечают | ❌ |
| РТС-тендер, ТЭК-Торг, ОТС | ⚠️ антибот | ❌ |
| **ЕИС (zakupki.gov.ru)** | ❌ **не отвечает** | ✅ |
| Сбербанк-АСТ | ❌ | ❌ |

ЕИС блокирует датацентровые адреса — не отвечает с VPS даже с отключённой
проверкой TLS. Поэтому у коннектора есть атрибут `location`
(`vps` / `home` / `any`), и сборщик берёт только «свои» площадки.

**Сейчас домашнего сборщика нет** (владелец отказался 04.08), значит
44-ФЗ и 223-ФЗ через ЕИС не собираются. Площадка заведена и помечена
«только из дома» — включить можно позже, подняв сборщик с `TR_LOCATION=home`.

Площадки с антиботом заведены диагностическими коннекторами: кнопка
«Опросить» даёт в журнале конкретную причину, а не тишину.

## Расписание и ручной поиск

Периодичность правится во вкладке, хранится в `settings` и
перечитывается сборщиком на каждом круге — перезапуск при смене не нужен.

Сборщик — отдельная служба `tenders-collector` (systemd, ставится
`scripts/setup-server.sh`). Отдельный процесс, а не поток внутри портала:
разбор чужих HTML не должен ронять API на одноядерном VPS. Nice=10 —
портал важнее. Ручной прогон (кнопка «Искать сейчас») умеет глубину в
днях, одно направление, одну площадку.

```bash
systemctl status tenders-collector
python tenders_collector.py --once   # один обход вручную
```

## Поисковые запросы к площадкам

Площадки делятся на два типа. **Листинговые** (Bidzaar) отдают всё за
период — забираем целиком и фильтруем у себя. **Поисковые**
(B2B-Center, `query_driven = True`) ищут по фразе.

Ключевой замер 04.08: у B2B-Center поиск требует ТОЧНОГО вхождения всей
строки. «персонал» находит 20 закупок, «аутсорсинг персонала» — **ноль**,
«погрузочно-разгрузочные работы» — тоже ноль. Мы слали длинные фразы и
сами себе резали выдачу.

Поэтому поисковым площадкам отдаются отдельные СЛОВА, а точная фраза
проверяется уже при отборе: площадка — широкое сито, а не финальный
фильтр. Замер после правки: **15 → 85 карточек** с B2B-Center по тем же
правилам.

Общие слова («услуги», «работы», «оказание») из запросов выкидываются —
по ним выдача случайная. Сравнение по ОСНОВЕ, а не по буквам: список
точных форм ломался на падежах.

## Грабли

- **Правка фильтра не должна удалять собранное.** `rematch_all` только
  снимает совпадения, строки тендеров остаются; выдача показывает лишь
  то, у чего есть хотя бы одно совпадение. Сузил город, передумал, вернул —
  всё на месте, повторно обходить площадки не нужно. Раньше здесь стоял
  DELETE, и снятие фильтра уже ничего не возвращало.
- **Молчаливый ноль хуже ошибки.** `_flush` считает упавшие записи, и
  прогон с падениями получает статус `partial`, а не `ok`. При переносе
  падала каждая запись (ошибся в имени поля `RawTender`), а журнал
  показывал «ok, найдено 0» — выглядело как рабочая система.
- **B2B-Center отдаёт 403 «голому» клиенту.** Нужен браузерный
  User-Agent (уже в `tenders_core/config.py`).
- Реестр площадок — из кода: появился коннектор, появилась строка в
  админке. Руками в базе площадки не заводить.
- Инициализация схемы ленивая, один раз на процесс. В тестах базу
  подменяют на каждый тест, поэтому там перезагружают `tenders_api`.
