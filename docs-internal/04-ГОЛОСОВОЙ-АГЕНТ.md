# 04 · Голосовой агент (автообзвон)

> Обновлено: 2026-07-17. Это сердце продукта — при изменении пайплайна,
> статусов или механизмов защиты обнови этот файл в том же коммите.

## Назначение

Загрузили базу кандидатов → бот сам звонит каждому по сценарию (вопросы:
актуальность, возраст, гражданство, стоп-факторы...) → на портале воронка с
вердиктами. Рекрутёр работает только с «годными» и помеченными «⚠ проверить».

## Файлы (все на ПК владельца, `voicecall/`)

| Файл | Роль |
|---|---|
| `dispatch_agent.py` | Главный цикл: поллинг портала, оркестрация звонков, пост-обработка |
| `phone_call.py` | Механика звонка: SIP/RTP (pyVoIP + 5 патчей), speak/listen, AGC, barge-in, диалоговый цикл |
| `dialog.py` | Логика сценария: шаги, распознавание ответов, детекторы (автоответчик/робот/ринг-бэк/перезвоните) |
| `stt.py` | Vosk: small-модель (реалтайм, грамматика) + big-модель 0.42 (пере-распознавание записи) |
| `tts.py` | edge-tts + Silero, кэш фраз (ключ: голос+скорость+trim-версия), обрезка тишины |
| `call_api.py` | Novofon Call/Data API (JSON-RPC через прокси VPS) |
| `silero_server.py` | Локальный TTS-сервер :5001 |
| `index.html` | Страница портала: кампании, воронка, карточки, конструктор сценариев |

## Пайплайн одного звонка

```
1. Агент поллит GET /voicecall/dispatch/poll (~20с) → кампания 'requested'
2. Прогрев: TTS-кэш фраз сценария (+имя кандидата), Vosk уже в памяти
3. POST /dispatch/claim → контакт (атомарно, status='calling')
4. Novofon start.employee_call: сначала звонок НАМ на SIP-линию 0125878,
   после ответа Novofon дозванивается кандидату (call_session_id)
5. Соединение = статус «Разговор» ОТ Novofon ИЛИ живая речь на линии
   (fallback _line_has_speech — Novofon у части номеров не переключает статус)
6. Диалог (_run_dialog_loop): для каждого шага сценария
   speak(вопрос, barge-in разрешён) → listen(Vosk small + грамматика шага + AGC
   до x9) → dialog.submit_answer → следующий шаг / переспрос / стоп
   На каждой реплике проверки: is_callback_request → is_voicemail_phrase →
   is_ringback_phrase (порядок важен!)
7. Итог → POST /dispatch/result (ответы, вердикт, транскрипт, duration_s)
8. ФОНОМ (поток): ждём запись у Novofon → прикрепляем mp3 →
   пере-распознавание обеих WAV-дорожек big-моделью → пере-валидация (см. ниже)
   → POST /dispatch/recheck-transcript
```

## Глоссарий статусов (для рекрутёров и разработчиков)

### Исход попытки звонка (`last_call_status`)

| Статус | На портале | Значит |
|---|---|---|
| `answered_completed` | дошёл до конца | человек ответил на все вопросы сценария |
| `no_answer` | не взял трубку | гудки/ринг-бэк, соединения не было. Перезвон уместен |
| `busy` | занято | — |
| `voicemail` | автоответчик | голосовая почта оператора ИЛИ робот-секретарь (Яндекс и пр.) |
| `low_recognition` | не распознали (не факт что автоответчик) | 3 вопроса подряд без распознанного ответа, при этом <2 осмысленных ответов собрано |
| `hangup_by_candidate` | оборвался | человек ответил и положил трубку посреди сценария; собранные ответы сохранены |
| `callback_requested` | просил перезвонить | живой человек: «наберите позже». Только ручной перезвон |
| `error` | ошибка звонка | сбой Novofon/SIP; авто-повтор 1 раз (attempts<2) |

### Вердикт (только для дошедших до конца)

| Вердикт | Значит |
|---|---|
| `passed` | годен — прошёл все вопросы без стоп-факторов |
| `stopped` | стоп — сработал стоп-фактор (судимость, не ищет работу...), причина в `stop_reason` |
| `declined` | отказ —技нически «не прошёл» без явного стопа |

### Двухфазный статус (`review_state`, с 17.07)

После звонка (дошёл/оборвался/не распознали) контакт получает бейдж
**«⏳ проверяется»** — вердикт предварительный, идёт пере-проверка по записи
(категория может измениться, напр. «годен» → «автоответчик»). Финализация:
рекчеком, либо агентом с ⚠ «без записи» (2 серии ретраев записи не помогли).
Недозвон/занято/ошибка — финал сразу.

### Флаг «⚠ проверить» (`needs_review` + `review_note`)

Ставится автоматикой, когда данным нельзя слепо верить: расхождение реалтайма
с записью, «годен» с ≥2 нераспознанными ответами, громко-но-пусто, автосверка
не подтвердила причину стопа. Рекрутёр обязан глянуть карточку.

## Механизмы защиты качества (выстраданы реальными тестами)

| Механизм | Где | От чего защищает |
|---|---|---|
| Грамматика Vosk по шагу (да/нет/числа) | `stt.py` | мусор в закрытых вопросах |
| AGC до x9 | `phone_call.py listen()` | тихие линии |
| Детектор автоответчика по фразам, на КАЖДОЙ реплике | `dialog._VOICEMAIL_PATTERN` | голосовая почта посреди разговора |
| Детектор AI-секретарей (фразы) | там же | Яндекс-роботы, ведущие диалог |
| Детектор ринг-бэка (≠ автоответчик!) | `dialog._RINGBACK_PATTERN` | «оставайтесь на линии» → это дозвон, исход no_answer |
| «Просит перезвонить» — проверяется ПЕРВЫМ | `dialog.is_callback_request` | живой человек не улетает в «автоответчик» |
| Пере-распознавание записи big-моделью | `dispatch_agent._recheck_transcript` | реалтайм-огрехи small-модели |
| Пере-валидация ответов LLM по записи | `_recheck_critical_answers` | возраст 20↔29, «красивая»→«российское»; итог в формате «X (по записи; реалтайм: Y)» |
| Grounding: значение принимается только если реально звучит в записи | `_answer_grounded`, `_age_grounded` | галлюцинации qwen3:1.7b |
| Только ДОСТИГНУТЫЕ вопросы пере-валидируются | там же | выдуманный возраст у бросивших трубку |
| LLM-классификация «человек/робот» для passed/stopped | `_llm_is_robot_secretary` | роботы, которых фразы не поймали (по умолчанию — «человек») |
| Переклассификация по записи | `reclassify_voicemail` / `reclassify_status` в recheck-эндпоинте | ложный «годен»/«отказ» → автоответчик; ринг-бэк → «не взял» |
| ≥2 осмысленных ответа + пропал → «оборвался», не «не распознали» | `_run_dialog_loop` | потеря собранных данных |
| Авто-повтор при error / опция «перезвон при недозвоне» | `vc_dispatch_result` | сбои Novofon; галочка при запуске кампании (по умолч. ВЫКЛ) |
| Memory-guard RTP с ПЕРЕ-БАЗИРОВАНИЕМ (не дропом!) | `phone_call._patch_rtp_memory_guard` | MemoryError-краш И потеря звука при разрыве RTP-timestamp базы |
| Ранний LLM-детект робота ВО ВРЕМЯ звонка (после 2 пустых шагов) | `dialog.llm_is_robot_live` + проба в `_run_dialog_loop` | роботы, доигрывавшие сценарий (83с медианы, 58 мин эфира на 129 контактов, тест 16.07) |
| Пост-LLM «человек/робот» (qwen3:1.7b) для ВСЕХ исходов с записью | `_recheck_transcript` шаг 0в | роботы в «не распознали»/«оборвался» (Надир-кейс). Реклассит в автоответчик |
| «Достигнутость» вопроса и по звучанию в записи | `_question_was_asked` в `_recheck_critical_answers` | живые с ответами в записи, оборванные по «3 без ответа» (Ахмединмухтор/Rohit) |
| «Поздний ответ»: недозвон с речью в записи → ⚠ | `_recheck_transcript` шаг 0г | человек взял трубку после таймаута (Анастасия-кейс) |
| LLM-саммари записи в review_note при ⚠ | `_llm_summary_for_review` | рекрутёр решает за 5 сек без прослушивания |
| Двухфазный статус «⏳ проверяется → финал» | `review_state` (main.py) + финализация рекчеком/агентом | слепые финальные «годен» без пере-проверки (4 шт в тесте 17.07) |
| Анти-мимикрия: «годен» без названного возраста → ⚠ (детерминированно) | `_passed_but_no_age` / `_candidate_stated_age` | «мимикрирующие» ассистенты Яндекса, игравшие живых (3 «чистых годен» 17.07). Проверено: 0 ложных на живых. НЕ реклассит — только флаг |
| Поведенческий детект уклончивости (2 подряд → LLM) | `dialog.answer_is_evasive` + `_run_dialog_loop` | говорящие роботы, не попадающие в пробу по нераспознанным |
| Ретраи записи: 2 серии + до 3 доп. раундов при СЕТЕВЫХ ошибках | `_fetch_and_attach_recording` | тест 21.07: запись существовала, но обе серии попали в обрыв сети — финализировались вслепую |
| Финализация «без записи» с флагом `no_recording` | recheck-эндпоинт (main.py) | плейсхолдер не затирает настоящий recheck параллельного потока (тест 21.07) |
| Grounding саммари: короткий транскрипт → пусто; число не из записи → саммари отброшено | `_llm_summary_for_review` | галлюцинация «возраст 25, москва, согласие — да» у кандидата, который не разговаривал (тест 21.07) |
| Точечный gzip крупных JSON | `_vc_maybe_gzip` (main.py) | зависание детализации кампании на плохой сети |
| Ранний отсев робота: длинная стартовая речь → свободная проба | `_early_robot_probe_reason` Слой 1 + `_free_probe_is_robot` | автоответчик доигрывал сценарий (медиана 88с ≈ 3 тариф. минуты). Живое «алло» коротко, приветствие робота 4-10с |
| Свободное распознавание на 1-м ходу при нераспознанной речи | там же, Слой 2 | робот проговаривается свободным текстом, грамматика да/нет его force-fit'ит |
| Потолок «нет прогресса» ~45с | там же, Слой 3 | робот топчется на 1-2 вопросе, живой к 35с уже ответил бы на несколько |
| Словарь шага «Возраст» без да/нет-слов | `dialog.vocab_for_step` (`_AGE_FRAMING`) | 50 слов-согласий конкурировали с числами и побеждали их: в карточках вместо возраста «конечно можно тринадцать ок думаю». Замер на шуме: разбор 67%→83% |
| Детерминированная сверка простых стопов «...: нет» | `_recheck_verdict` (пре-чек до LLM) | LLM давала ложное ⚠ на 15 из 16 стопов «не ищу работу» (короткая запись → «неразборчиво») |
| Возраст из записи — сначала парсером, потом LLM | `_recheck_critical_answers` | малая LLM восстановила 1 из 79; парсер числительных берёт число без риска галлюцинации |
| Корзины: техсбой и «обрыв без ответов» → НЕ спорные | `_vc_categorize_contact` (`answers_count`) | рекрутёр разбирал 10 наших техсбоев и 21 обрыв без данных. Замер: спорные 38%→23% |
| Авто-повтор «бросил трубку молча» | `vc_dispatch_result` (`silent_hangup`) | живой номер с нулём данных получает второй набор вместо ручного разбора |
| «Просит перезвонить» ловится и короткими фразами | `dialog.is_callback_request` | «перезвоните позже»/«наберите позже» давали False (требовался личный маркер) — живые уезжали в спорные |

## Патчи pyVoIP (все в `phone_call.py`, с комментариями-обоснованиями)

1. `_patch_pyvoip_proxy_auth` — 407 Proxy-Auth от Novofon (иначе INVITE не работает)
2. `_patch_pyvoip_ack_tag` — корректный branch в ACK
3. `_patch_rtp_logging` — входящий кодек + счётчик RTP-пакетов (ключевая диагностика NAT-vs-буфер)
4. `_patch_pcma_encode_bug` — копипаст-баг pyVoIP: PCMA кодировался как PCMU
5. `_patch_rtp_memory_guard` — forward-скачок timestamp → пере-базирование буфера

## Известные грабли (НЕ повторять)

- «Работало, а теперь нет» = регрессия наших правок, а не среда. Сначала diff
  с последнего рабочего состояния, потом теории про NAT/сеть.
- RTP-пакеты идут + тишина на чтении = баг буфера/guard, НЕ NAT.
- Фразы ринг-бэка нельзя добавлять в автоответчик (теряются живые, взявшие
  трубку после гудка).
- Нераспознанные ответы живут в `sess.notes`, а НЕ в `sess.answers` — любой
  подсчёт «не распознано» должен смотреть в оба словаря.
- VPS не тянет модели (960 МБ RAM) — не переносить туда ничего тяжёлое.
- После правки `voicecall/*.py` — перезапуск задачи `STH-Dispatch-Agent`, иначе
  старый код продолжает звонить.
