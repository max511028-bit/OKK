## VPS (root@195.208.119.67, portalsth.ru, Ubuntu, 1 vCPU / 960 МБ)

```
/var/www/okk/                ← весь репозиторий (rsync из CI)
├── tasks/api/               ← бэкенд
│   ├── .venv/               ← uvicorn запускается отсюда
│   ├── tasks.db             ← ЕДИНСТВЕННАЯ боевая БД (SQLite). НЕ в git. Бэкапь!
│   └── auth_secret.bin      ← HMAC-секрет токенов (генерится сам)
├── sales/                   ← перекрыт собранным dist (см. CI)
└── recruiter/service_account.json  ← кладёт CI из GitHub Secrets
```

| Сервис | Что | Команды |
|---|---|---|
| `tasks-api.service` | uvicorn main:app :8601 | `systemctl restart/status tasks-api`, логи `journalctl -u tasks-api` |
| nginx | статика + прокси `/tasks/api/*`→8601, `/novofon-*api/`→Novofon, recruiter→8501 | конфиги генерит `scripts/setup-server.sh` |
| sshd | принимает reverse-туннель с ПК (21434 Ollama, 25001 Silero) | `ss -lnt \| grep 2143` |

⚠️ Особенности VPS: SSH-сессии с удержанием обрываются (только one-liner'ы);
RAM впритык — не ставить ничего тяжёлого; SQLite-бэкапов пока НЕТ (техдолг №1).

## CI/CD (GitHub Actions, `.github/workflows/deploy.yml`)

Триггер: push в `main`. Шаги:
1. Сборка `sales/` (npm ci + vite build).
2. `rsync -avz --delete` репо → `/var/www/okk/` (исключая sales/dist — он поверх, без --delete, чтобы не стереть загруженные CSV).
3. Заливка `service_account.json` из секрета.
4. `setup-server.sh` на VPS: nginx-снипеты + **restart tasks-api**.
5. Smoke-тест: `/health`, `/ai/health` и др. — CI падает, если портал не 200.

Время цикла ~3-4 минуты. Секреты CI: `VPS_SSH_KEY`, `GOOGLE_SERVICE_ACCOUNT_INFO`
(GitHub → Settings → Secrets → Actions).

## Что деплоится КАК (шпаргалка)

| Изменил | Как доставить |
|---|---|
| `tasks/api/main.py`, тесты | push → CI сам (restart tasks-api включён) |
| статические фронты (`*/index.html`) | push → CI (rsync) |
| `sales/src/*` | push → CI (соберёт сам) |
| `voicecall/*.py` (агент) | **локально**: перезапуск задачи `STH-Dispatch-Agent` (репо на ПК = рабочая копия агента) |
| `voicecall/index.html` | push → CI (это страница портала, не агент) |
| миграции БД | внутри `init_db()` → применяются при restart tasks-api |
| скрипты автозапуска ПК | руками на ПК (планировщик), см. ниже |

## ПК владельца — автозапуск (Windows 11, вход юзера обязателен)

4 задачи планировщика, **все user-context, триггер «при входе», через VBS-шим
`C:\ProgramData\sth\run-hidden.vbs`** (прямой powershell = вспышки окон, не делать):

| Задача | Скрипт | Держит |
|---|---|---|
| `STH-Dispatch-Agent` | `scripts/run-dispatch-agent.ps1` (цикл+рестарт при краше, лог `C:\ProgramData\sth\dispatch-agent.log`) | звонилку |
| `STH-Ollama-Serve-User` | `%LOCALAPPDATA%\sth\ollama-startup.ps1` | Ollama :11434 |
| `STH-AI-Tunnel-User` | `scripts/start-ai-tunnel.ps1` (цикл ssh -R, precleanup зомби на VPS) | туннель |
| `STH-Portal-Watchdog` | `scripts/sth-ai-watchdog.ps1` (при входе + каждый час) | чинит Ollama+Silero+туннель, toast при сбое |

Известный зомби: осиротевшая SYSTEM-задача туннеля (не видна в Get-ScheduledTask),
падает на чтении ключа — безвредна, вычистить можно только от админа (техдолг).
