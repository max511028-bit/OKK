## Общее

- **SQLite**, один файл: `/var/www/okk/tasks/api/tasks.db` на VPS (в git не попадает).
- Схема и миграции — в `init_db()` в `tasks/api/main.py` (выполняется при старте
  tasks-api). Миграция = `ALTER TABLE ... ADD COLUMN` в `try/except OperationalError` —
  идемпотентно, безоткатно. **Отдельных файлов миграций нет.**
- Один писатель (tasks-api), поэтому SQLite достаточно.
- ⚠️ Автоматических бэкапов НЕТ (техдолг №1 в `10-ТЕХДОЛГ.md`).

## Таблицы (14)

### Ядро обзвона (главные данные бизнеса)

**`voicecall_campaigns`** — кампания обзвона (одна загрузка базы)
| Колонка | Тип | Что |
|---|---|---|
| id, name, created_at | | |
| scenario_id, scenario_name | TEXT | какой сценарий озвучивается |
| total | INT | контактов загружено |
| source | TEXT | HH / Avito / manual / mix |
| dispatch_state | TEXT | idle → requested → running → done (жизненный цикл автообзвона) |
| dispatch_paused | INT | пауза (текущий звонок доигрывается) |
| retry_no_answer | INT | галочка «перезвон при недозвоне» (фиксируется при запуске) |

**`voicecall_contacts`** — один кандидат в кампании
| Колонка | Что |
|---|---|
| campaign_id → campaigns | |
| name, phone (нормализован 7XXXXXXXXXX), source, raw_data_json | вся строка из Excel сохраняется |
| status | pending / calling / done / skipped / failed |
| verdict, stop_reason | итог для дошедших (passed/stopped/declined) |
| attempts, last_attempt_at | счётчик попыток (лимитирует авто-повторы) |
| validation_id → candidate_validations | последняя попытка |
| known_answers_json | предзаполненные ответы из файла (пропускаются в диалоге) |
| screen_out_reason | отсев ДО звонка (предпроверка) |
| last_call_status | точный исход: no_answer/voicemail/low_recognition/... (см. 04) |
| dropped_at_step | на каком вопросе оборвался |

**`candidate_validations`** — одна ПОПЫТКА звонка/анкеты (история всех попыток контакта)
| Колонка | Что |
|---|---|
| project_id/project_name | сценарий |
| started_at, ended_at, verdict (NOT NULL!), stop_reason | |
| answers_json | {вопрос: ответ}; нераспознанные — «не распознано: <услышанное>»; пере-валидированные — «X (по записи; реалтайм: Y)» |
| transcript_json | [{who, text}] живой диалог |

| recheck_transcript | пере-распознавание записи big-моделью (обе дорожки) |
| needs_review, review_note | флаг «⚠ проверить» + почему |
| duration_s | длительность попытки (в т.ч. недозвона) |

### Задачник

- **`tasks`** — id, title, **data (JSON-блоб всей задачи)**, created/updated, deleted_at
  (мягкое удаление, корзина 7 дней). Вложения — файлы на диске VPS.
- **`task_history`** — события задач (task_id, event, ts).
- **`lists`** — именованные списки (доски/справочники), data = JSON.

### AI-подсистема

- **`ai_logs`** — каждый LLM-запрос: dashboard, вопрос/ответ, токены, латентность, cache_hit.
- **`ai_cache`** — кэш ответов (key = хэш), hit_count.
- **`ai_test_runs`** — smoke-прогоны AI по расписанию/кнопке.
- **`ai_chats`** — чаты модуля chat (messages = JSON).

### Прочее

- **`dash_blobs`** — JSON-блобы дашбордов month/sales (ключ-значение).
- **`analyst_projects`** — проекты аналитика: payload_json + read_token (шеринг по ссылке), view_count.
- **`kp_history`** — история КП: payload JSON, is_template.

## Связи (текстом)

```
voicecall_campaigns 1—N voicecall_contacts 1—N candidate_validations
voicecall_scripts (scenario_id по slug, без FK)
tasks 1—N task_history
```

## Правила работы со схемой

1. Новая колонка — ТОЛЬКО через идиому миграции в `init_db()` (см. существующие блоки).
2. NOT NULL-колонки в старых таблицах (напр. `candidate_validations.verdict`) —
   реальный источник багов при UPDATE в NULL; проверяй схему перед записью.
3. Данные-JSON (answers_json и пр.) читать через try/except — легаси-строки бывают кривыми.
